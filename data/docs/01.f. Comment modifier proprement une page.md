#Comment modifier proprement une page contenu dans le framework SAND

Tout d’abord il vous faut reconnaitre le nom de la page suivant le routage pour aller chercher les bons fichiers à modifier dans le dossier `include`. 

Par exemple : pour la page `index`, les bon fichiers à modifier sont :

-	`application/include/controlleurs/index.php`
-	`application/include/modeles/index.model`
-	`application/include/vues/view/index.blade.php` ou `application/include/vues/view/index.html.twig`

Si vous désirez modifier le comportement d’une page il vous faudra très certainement modifier le contrôleur et la vue associée, voire peut-être l’action et sa vue si la vue mère fait des appels de ce type.

Les actions se trouve dans le dossier `application/include/actions/` et leurs vues sont dans le même dossiers que les vues mères : `application/include/vues/view/`, il convient de la préfixer par `action-actionnamedescription`.

Le `.model` de la page contient une variable engine qui peut prendre les valeurs `blade` ou `twig`. Par défaut si ce paramètre de modèle n’est pas renseigné c’est le moteur de rendu `blade` qui sera appelé.

Si vous désirez juste modifier l’affichage, il vous suffira simplement de modifier la vue `blade` ou `twig` suivant le moteur de rendu.

Cependant si vous désirez modifier le `head` ou le `layout` de la page vous devrez modifier les fichiers dans `application/include/vues/system/` ou `application/include/vues/layout/`

## Syntaxe des valeurs d’un `.model`

Chaque ligne d’un `.model` a la forme `cle : valeur`. Les espaces autour de la clé et de la valeur sont ignorés. `SAND\Classe\Modele` lit la valeur ainsi :

- `texte` : une chaîne, par exemple `engine : twig` ;
- `{a, b}` : une liste de chaînes, par exemple `ariane : {accueil, page}` donne `['accueil', 'page']` ;
- dans une valeur `{…}`, chaque élément `[…]` devient un sous-tableau :
  - `[]` donne un tableau vide ;
  - `[cle=valeur, cle2=valeur2]` donne un tableau associatif ;
  - `[a, b]` donne une liste ;
  - un élément simple et un sous-tableau peuvent se mélanger : `{x, [k=v]}` donne `['x', ['k' => 'v']]`.

Les sous-tableaux servent aux paramètres d’URL du fil d’Ariane, alignés élément par élément sur `ariane` et `arianelink` :

```
ariane : {accueil, page}
arianelink : {index, page}
arianeparams : {[], [id=4]}
```

Chaque sous-tableau se passe tel quel à `Url::link_rewrite(false, $arianelink[$i], $arianeparams[$i])`, qui attend un tableau associatif `cle => valeur` et produit `/page/id/4` (une liste `[a, b]` donnerait `/page/0/a/1/b`).

Limites :

- un seul niveau : un `[` à l’intérieur d’un `[…]` reste du texte (`{[[a]]}` donne `[['[a]']]`) ;
- les valeurs `{…}` tiennent sur une seule ligne et doivent occuper toute la valeur ;
- la clé ne contient que des lettres non accentuées, `_` et `+` ; la valeur, elle, admet tout caractère sauf le retour à la ligne (`.`, `/`, `:`, `%`, `€`, `’`…) : `page_title : Accueil : bienvenue` donne `Accueil : bienvenue`, le premier `:` séparant la clé ;
- dans un sous-tableau, le premier `=` sépare la clé de la valeur : `[url=https://exemple.org/x?y=1]` donne `['url' => 'https://exemple.org/x?y=1']` ;
- une virgule ne peut pas figurer dans un élément de `{…}` ni dans une valeur de sous-tableau : elle sépare toujours deux éléments, et rien ne permet de l’échapper ;
- des crochets mal formés (`{[a, b}`, `{[k=v], ]}`) sont signalés dans le journal `app.modele.log` (nom du `.model` et clé) ; la valeur est lue telle quelle, les morceaux mal formés restant du texte.
