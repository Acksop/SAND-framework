# Les actions

## Définition

Une action est un fragment de gabarit appelé par une fonction depuis un gabarit mère (une vue, un layout), avec la possibilité d'accéder dynamiquement à la base de données au moment de l'appel. Elle sert à insérer dans une page un bloc qui a sa propre logique : une liste déroulante, un menu, un compteur.

Une action est formée de deux fichiers :

* une classe `application/include/actions/<Objet>Action.php` qui étend `MVC\Classe\Implement\Action` ; ses méthodes `render…()` calculent les données et rendent un gabarit ;
* un gabarit `application/include/vues/view/action-<…>.blade.php` (ou `.html.twig`) que la méthode rend.

La convention est donc `<Objet>Action::render…()` pour la méthode et `action-…` pour le gabarit ; les noms suivent l'[annexe 20](20.%20Annexe%20-%20Convention%20de%20nommage%20et%20m%C3%A9thodes%20HTTP.md).

Exemple, aligné sur l'action de test du dépôt (`tests/phpunit/tests/TestAction.php`) :

```php
<?php

class OrganismeAction extends \MVC\Classe\Implement\Action
{
    public function renderSelect($choisi = null, $moteur = 'blade')
    {
        // accès dynamique à la base, au moment de l'appel (requête de votre choix)
        $organismes = $this->chargerOrganismes();

        return $this->render('action-organisme-select', ['organismes' => $organismes, 'choisi' => $choisi], $moteur);
    }

    private function chargerOrganismes(): array
    {
        return []; // à remplacer par la lecture en base
    }
}
```

Appel depuis un gabarit Blade :

```php
<?php echo \MVC\Classe\ControlleurAction::inserer('organisme.renderSelect', []); ?>
```

Appel depuis un gabarit Twig (la fonction `action` est déclarée sûre : le HTML retourné par l'action est inséré tel quel, sans `|raw`) :

```php
{{ action('organisme.renderSelect', []) }}
```

> **Sécurité.** La sortie d'une action est insérée telle quelle dans la page : l'action est responsable de l'échappement de toute donnée venant d'un utilisateur.
>
> * En Blade, `{{ }}` affiche en brut : une donnée utilisateur s'affiche avec `{{{ }}}`, jamais avec `{{ }}`.
> * En Twig, n'ajoutez jamais `|raw` sur une donnée utilisateur.
> * Une action ne renvoie jamais une chaîne non maîtrisée (retour de `renderJSON`, sortie d'un tampon, texte venu de la base ou de la requête) sans l'avoir échappée.

Le texte avant le point (`organisme`) désigne la classe `OrganismeAction` ; le texte après (`renderSelect`) la méthode. Sans point, la méthode `default()` est appelée.

## Changement de comportement : `render(..., 'twig')`

`Action::render($vue, $donnees, 'twig')` rend désormais **vraiment en Twig**. Avant, l'argument était ignoré et Blade servait toujours. Conséquences :

* le gabarit `.html.twig` doit exister (par exemple `action-organisme-select.html.twig`), sinon le rendu échoue ;
* Twig échappe automatiquement les valeurs ; Blade garde son comportement de Blade 4 (`{{ }}` brut, `{{{ }}}` échappé) ;
* un moteur inconnu lève une `InvalidArgumentException`.

Le détail des ruptures (dont la correction `include/action/` en `include/actions/`) est dans `UPGRADE.md` à la racine du dépôt.

## Exemple (illustratif)

Les actions se trouvent dans `application/include/actions/`. Pour un exemple qui s'exécute réellement, voir `TestAction` et `RenduTest` dans `tests/phpunit/tests/`. Exemple tiré de `DefaultAction` :

```php
<?php  
  
use MVC\Classe\HttpMethodRequete;  
use MVC\Classe\Implement\Action;  
use MVC\Classe\Url; 
  
class DefaultAction extends Action  
{  
  public function default($data1 = null,$data2 = null,$data3 = null)  
 {  
	  /**your action algorythm**/  
	  if ($data1 !== null) {  
		  $var1 = $data1;  
	  } else {  
		  $var1 = 1;  
	  }
	  if ($data2 !== null) {  
		  $var2 = $data2;  
	  } else {  
		  $var2 = 2;  
	  }
	  if ($data3 !== null) {  
		  $var3 = $data3;  
	  } else {  
		  $var3 = 3;  
	  }  
	  return $this->render('action', array('var1' => $var1, 'var2' => $var2, 'var3' => $var3));  
 }  
  public function variableSlug($data1,$data2)  
 {  
	 /**your action algorythm**/  

	 ob_start();
	 print_r($data1);
     echo "<br/>";
     print_r($data2);
	 return ob_get_clean();
 }  
  public function makeHttp11()  
 {  
	  $data = array('myval' => 25);  
	  
	  $request = new HttpMethodRequete();  
	  $request->setUrl(Url::absolute_link_rewrite(false,'accueil',['var10'=>'val10']))->get($data);  
	  $request->setUrl(Url::absolute_link_rewrite(false,'accueil',['var10'=>'val10']))->post($data);     				
	  $request->setUrl(Url::absolute_link_rewrite(false, 'accueil', ['var10' => 'val10']))->put($data);  
	  $request->setUrl(Url::absolute_link_rewrite(false,'accueil',['var10'=>'val10']))->delete($data);  
  }  
}
```

Avec cet accès dans une vue Blade :
```php
  
<?php echo \MVC\Classe\ControlleurAction::inserer('default.default',[4,5,6]); ?>  
<?php echo \MVC\Classe\ControlleurAction::inserer('default.makeHttp11',[]); ?>
```
ou avec cet accès dans une vue Twig :
```php
{{ action('default.defaultTwig',[4,5,6]) }}
{{ action('default.makeHttp11',[]) }}
```


Il faut absolument que l'action retourne du texte, soit par la méthode `render`, soit par un système de tampon (`ob_start()` / `ob_get_clean()`).
