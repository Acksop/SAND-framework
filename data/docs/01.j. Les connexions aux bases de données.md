# Les connexions aux bases de données

La classe `MVC\Classe\Bdd` ouvre des connexions PDO **nommées**. Chaque nom correspond à un jeu de constantes déclarées dans `application/config/bdd-parameters.php` (copie locale de `bdd-parameters.php.skel`, à ne jamais versionner).

## Déclarer une connexion

Pour une connexion nommée `<nom>`, déclarer trois constantes, le suffixe étant le nom en majuscules :

```php
define('DSN_BDD_ANNUAIRE', "mysql:host=localhost;dbname=annuaire;charset=utf8mb4");
define('USER_BDD_ANNUAIRE', "utilisateur");
define('PASS_BDD_ANNUAIRE', "mot_de_passe");
```

+ `DSN_BDD_<NOM>` est obligatoire. `USER_BDD_<NOM>` et `PASS_BDD_<NOM>` sont facultatives (chaîne vide par défaut, utile pour SQLite).
+ Dans le nom, tout caractère autre que lettre, chiffre ou `_` devient `_` : `new Bdd('annuaire-2')` lit `DSN_BDD_ANNUAIRE_2`. La casse ne compte pas : `annuaire` et `ANNUAIRE` désignent la même connexion.
+ **Forme historique :** si `DSN_BDD_<NOM>` n'existe pas, `Bdd` lit `DSN_<NOM>`, `USER_<NOM>` et `PASS_<NOM>`. C'est ce qui permet aux connexions `bdd1` et `bdd2` du modèle (`DSN_BDD1`, `DSN_BDD2`) de continuer à fonctionner. Si les deux formes existent, `DSN_BDD_<NOM>` l'emporte.
+ La connexion `default` lit `DSN_BDD_DEFAULT`, `USER_BDD_DEFAULT` et `PASS_BDD_DEFAULT`.
+ Un nom sans constante lève une `RuntimeException` qui indique les constantes à définir (le message ne contient ni DSN ni mot de passe).

## Utiliser une connexion

```php
$bdd = new \MVC\Classe\Bdd();            // connexion 'default'
$bdd = new \MVC\Classe\Bdd('bdd1');      // forme historique DSN_BDD1
$bdd = new \MVC\Classe\Bdd('annuaire');  // DSN_BDD_ANNUAIRE

$pdo = \MVC\Classe\Bdd::connexion('annuaire');       // l'objet PDO lui-même
[$dsn, $user, $pass] = \MVC\Classe\Bdd::identifiants('annuaire'); // résolution seule, sans connexion
```

Une seule connexion PDO est ouverte par nom pendant la requête : deux `new Bdd('annuaire')` partagent le même objet PDO (`$bdd->bdd`). Les connexions sont configurées en `PDO::ERRMODE_WARNING` et `PDO::FETCH_ASSOC`.

## Déclarer la connexion d'une page : clé `bdd` du `.model`

Une page peut déclarer sa connexion dans son fichier `.model` :

```
name : annuaire
page_title : Annuaire
bdd : annuaire
```

Dans le contrôleur de la page, la définition de la page est disponible dans `$page_params` :

```php
$bdd = \MVC\Classe\Bdd::pourPage($page_params); // connexion 'annuaire', ou 'default' sans clé bdd
```

`Bdd::pourPage()` prend la clé `bdd` (espaces retirés). Sans clé `bdd`, ou avec une valeur vide, la connexion est `default`. Une valeur qui n'est pas un nom (un tableau `{…}`, par exemple) lève une `InvalidArgumentException`. `Bdd::nomPourPage()` renvoie le nom retenu sans ouvrir de connexion.

> **Règle :** `Bdd::pourPage()` ne s'utilise **qu'avec une définition de page issue d'un `.model`**, jamais avec des paramètres d'URL (`$_GET`, `$page_params['all_params']`, paramètres d'une route). Le choix de la base doit venir de la configuration de l'application, pas du visiteur.

## Requêtes et erreurs

`faireBindRequete($sql, $params)` prépare, lie et exécute la requête. Elle renvoie le `PDOStatement`, ou **`0`** en cas d'échec (préparation, exécution ou `PDOException`). L'échec est journalisé dans `application/logs/app.error.log` avec le nom de la connexion et le contenu de `errorInfo()` (SQLSTATE, code du pilote, message). Le journal ne contient jamais le DSN, l'utilisateur ni le mot de passe.

```php
$req = $bdd->faireBindRequete($sql, [['categorie', $categorie, \PDO::PARAM_INT]]);
if ($req === 0) {
    // l'erreur est dans app.error.log
}
$lignes = $bdd->exploiterResultat($req);   // fetchAll()
$nombre = $bdd->exploiterNbResultat($req); // rowCount() : lignes touchées par un INSERT, UPDATE ou DELETE
```
