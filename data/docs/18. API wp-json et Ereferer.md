# API wp-json et Ereferer

SAND embarque, dans le dossier `api/` à la racine du dépôt, une API REST dont les adresses imitent celles de WordPress (`/wp-json/…`). Elle sert à deux choses :

- répondre proprement aux robots et aux outils qui sondent `/wp-json/wp/v2/posts`, `pages`, `categories`, `comments` et `tags`. Le site n'est pas un WordPress : ces ressources répondent 404 en JSON ;
- recevoir les articles poussés par le réseau ereferer.com (plugin WordPress « Article submit »), sur `/wp-json/v1/ereferer` ou `/api/v1/ereferer`.

## Ordre de traitement dans `Application`

`public/index.php` crée `new \MVC\Classe\Application()` puis appelle `launch()`.

1. Dans le constructeur, si le chemin de la requête commence par `/wp-json` ou `/api` (après `BASE_SERVER_DIRECTORY`), l'application se contente de noter `$this->api = true`. Elle n'instancie ni `HttpMethod`, ni `Browser`, ni `Url`, ni `Dispacher`.
2. `launch()` appelle alors `\MVC\Api\Component\Router::dispatch()`, qui émet la réponse JSON. Aucun `Controlleur` n'est créé.
3. Pour tout autre chemin (`/index`, `/ma-page`…), le comportement est inchangé.

La reconnaissance du chemin est stricte :

- les barres obliques répétées sont ignorées (`//wp-json/…` est bien l'API) ;
- la casse doit être exacte (`/WP-JSON/…` n'est pas l'API) ;
- `%2F` n'est pas décodé (`/wp-json%2Fv1…` n'est pas l'API).

Ces deux derniers chemins suivent le routage MVC, comme toute page inconnue.

### Maintenance

Par défaut, l'API reste joignable pendant une maintenance du site (`APP_STATE` vaut `CLOSED` ou `MAINTAINED`, ou plage `MAINTENANCE_DATE_DEBUT`/`FIN`). Pour la fermer elle aussi, ajoutez `define('API_PENDANT_MAINTENANCE', false);` dans `app-parameters.php`. Pendant la maintenance, elle répond alors **503** en JSON, avec l'en-tête `Retry-After`.

### `public/.htaccess`

Le `public/.htaccess` envoie à `index.php` tout chemin qui n'est pas un fichier existant, `/wp-json/…` et `/api/…` compris.

Pour les seuls chemins de l'API, il recopie aussi l'en-tête `Authorization` dans `HTTP_AUTHORIZATION`, parce qu'Apache ne le transmet pas toujours à PHP-FPM. Avec Apache 2.4.13 ou plus, `CGIPassAuth On` est une alternative.

```
RewriteCond %{HTTP:Authorization} .+
RewriteRule ^(wp-json|api)(/|$) - [E=HTTP_AUTHORIZATION:%{HTTP:Authorization}]
```

## Méthodes HTTP

L'API REST est le **seul endroit du framework où d'autres verbes que GET et POST sont admis** (voir `20. Annexe - Convention de nommage et méthodes HTTP.md`).

| Requête | Action appelée sur le contrôleur |
|---|---|
| `GET /wp-json/{ns}/{ressource}` | `getItems()` |
| `GET /wp-json/{ns}/{ressource}/{id}` | `getItem($id)` |
| `HEAD …` | comme `GET`, sans corps de réponse |
| `POST /wp-json/{ns}/{ressource}` | `createItem($body)` |
| `PUT` ou `PATCH /wp-json/{ns}/{ressource}/{id}` | `updateItem($id, $body)` |
| `DELETE /wp-json/{ns}/{ressource}/{id}` | `deleteItem($id)` |
| `OPTIONS …` | `schema()` : description des actions, lue dans leur PHPDoc |

`{ns}` vaut `v1`, `v2`… ; `/wp-json/wp/v2/…` désigne les contrôleurs `MVC\Api\Controller\wp\v2\…`. Le préfixe `/api/` est équivalent à `/wp-json/`.

Les arguments d'une action sont pris par nom dans la chaîne de requête (`?page=2&per_page=10`) et convertis selon le type déclaré. Un paramètre sans `=` vaut `''`. Le corps JSON arrive dans `$body`.

Le corps n'est lu **qu'après** l'authentification. Il est limité à `API_TAILLE_MAX_CORPS` octets (défaut 1 Mo, soit `1048576`) : au-delà, la réponse est 413. Le JSON est décodé avec une profondeur maximale de 32 niveaux. Un corps non vide qui n'est pas un objet ou un tableau JSON, ou qui est trop profond, donne 400.

Une action renvoie un tableau (réponse 200) ou une `MVC\Api\Component\Response` (statut libre). Elle ne fait jamais d'`echo` ni de `die()`.

## Réponses et erreurs

| Statut | Cas |
|---|---|
| 400 | corps JSON invalide ou trop profond |
| 404 | chemin ou ressource inconnus ; ressources `wp/v2` en `GET` et `HEAD` |
| 401 | méthode d'écriture sans clé **ou** avec une clé invalide (même message, en-tête `WWW-Authenticate: Bearer`) |
| 405 | action absente pour cette méthode (en-tête `Allow` ; le message ne reprend pas la méthode reçue) |
| 413 | corps plus long que `API_TAILLE_MAX_CORPS` |
| 501 | action volontairement non implémentée (écritures `wp/v2`) ; Ereferer sans dépôt configuré |
| 503 | maintenance en cours avec `API_PENDANT_MAINTENANCE` à `false` |
| 500 | toute autre exception. Hors débogage, le message est `Erreur interne`. Le journal `application/logs/app.api.log` ne garde que la classe de l'exception et son message, tronqué à 160 caractères sur une ligne : ni trace, ni chemin, ni corps de la requête. En débogage (`DEBUG === true`), le message de l'exception est renvoyé au client |

`OPTIONS` renvoie le nom court de la ressource (`ereferer`), jamais le nom de classe interne.

Une erreur voulue se lève avec `throw new \MVC\Api\Component\ApiException('message', 404);` : son message est renvoyé au client.

## Clés d'API

`GET`, `HEAD` et `OPTIONS` sont publics. `POST`, `PUT`, `PATCH` et `DELETE` exigent l'en-tête `Authorization: Bearer <clé>`. La méthode est mise en majuscules avant la vérification : `post` exige donc aussi la clé.

1. Copiez le modèle : `cp api/config/api_keys.php.skel api/config/api_keys.php`. La copie est ignorée par git (`.gitignore`) : ne la versionnez jamais.
2. Générez une clé : `php -r "echo bin2hex(random_bytes(32)), PHP_EOL;"` et transmettez-la au client (ereferer.com).
3. Dans `api_keys.php`, remplacez la valeur factice. Mieux, écrivez directement l'empreinte, calculée hors du dépôt :

```php
define('API_KEYS', [
    '<empreinte sha256 de la clé>' => 'ereferer',
]);
```

La clé reçue est hachée en SHA-256, puis comparée avec `hash_equals()`. Les empreintes sont normalisées en minuscules. La valeur factice du modèle n'est jamais acceptée, même si son empreinte est écrite en majuscules.

Les constantes `API_FICHIER_CLES` et `API_FICHIER_ROUTES` (valeurs par défaut dans `application/config/constantes-par-defaut.php`) permettent de ranger ces fichiers ailleurs.

## Routes explicites

Pour une adresse hors convention (recherche, sous-ressource), déclarez la route dans `api/config/routes.php`. Elle est essayée avant la convention. Le fichier est livré sans route active, avec un exemple en commentaire. Les requêtes SQL passent toujours par des requêtes préparées (`Bdd::faireBindRequete()`).

**Attention :** une route `GET` déclarée ici est **publique**, sans clé, comme toute lecture. Une route qui expose des données réservées doit être déclarée en `POST` (clé exigée), ou vérifier elle-même un droit d'accès.

```php
$registre->register('GET', 'v1/articles/(?P<id>\d+)', function (array $params, array $corps) {
    // renvoie un tableau ou une Response
});
```

## Ereferer

`POST /wp-json/v1/ereferer` (ou `/api/v1/ereferer`) reprend le contrat du plugin « Article submit ». Le framework authentifie la requête et valide les champs. L'enregistrement est confié à l'hôte.

### Champs reçus (corps JSON)

| Champ | Type | Règle |
|---|---|---|
| `test_connection` | bool | si vrai : vérification de la clé, rien n'est enregistré |
| `id` | entier positif | obligatoire (identifiant de l'article chez ereferer) |
| `delete` | bool | si vrai : suppression de la soumission `id` |
| `post_title` | chaîne non vide, 255 caractères au plus | obligatoire pour un enregistrement |
| `post_content` | chaîne non vide, 200 000 caractères au plus | obligatoire pour un enregistrement |
| `categories` | liste de 20 valeurs simples au plus | facultatif |
| `front_image` | URL `http(s)`, 2 048 caractères au plus | facultatif |
| `meta_title`, `custom_field` | chaîne, 255 caractères au plus | facultatifs (`custom_field` : source de l'image) |
| `meta_description` | chaîne, 500 caractères au plus | facultatif |
| `force` | bool | republier une soumission déjà publiée |

Les booléens (`test_connection`, `delete`, `force`) passent par `filter_var(…, FILTER_VALIDATE_BOOLEAN)` : la chaîne `"false"` vaut faux. Le corps compte au plus 50 entrées au premier niveau. Toute limite dépassée donne 422. Ces limites sont les constantes `Ereferer::LONGUEURS_MAX`, `CATEGORIES_MAX` et `ENTREES_MAX`.

### Réponses

| Cas | Statut | `code` |
|---|---|---|
| aucun dépôt configuré | 501 | `not_implemented` |
| test de connexion | 200 | `success_connection` |
| `id` absent ou invalide | 422 | `incorrect_post_id` |
| titre ou contenu vide ou trop long | 422 | `incorrect_post` |
| autre champ mal typé ou hors limite, plus de 50 entrées | 422 | `incorrect_field` |
| enregistrée, en attente | 200 | `publish_pending` (`article_url` nul) |
| enregistrée, publiée | 200 | `publish_success` (`article_url` renseigné) |
| déjà publiée, sans `force` | 409 | `post_not_editable` |
| suppression faite ou inconnue | 200 ou 404 | `success_delete` ou `failed_delete` |
| `GET`, `HEAD`, `PUT`, `PATCH`, `DELETE` | 405 | |

Toutes ces réponses portent `status` (booléen), `code` et `message`.

### Brancher le stockage : `DepotSoumissions`

L'hôte (B25 ou toute autre application) écrit une classe qui implémente `MVC\Api\Contract\DepotSoumissions`, puis la déclare dans `app-parameters.php` :

```php
define('API_DEPOT_SOUMISSIONS', \MonApplication\Api\DepotSoumissionsBreves::class);
```

La valeur par défaut est `null`, auquel cas la route répond 501. Une classe introuvable, ou qui n'implémente pas l'interface, donne un 500, journalisé.

La classe est instanciée sans argument et doit être chargeable par l'autoload de Composer. Elle reçoit des champs **déjà validés** :

| Clé | Contenu |
|---|---|
| `id_externe` | `id` reçu, en chaîne |
| `titre` | titre, nettoyé de l'espace fine encodée `%e2%80%89` |
| `contenu` | HTML brut : **à assainir par l'hôte** avant affichage |
| `categories` | liste |
| `image`, `meta_titre`, `meta_description`, `source_image` | chaîne ou `null` |
| `forcer` | bool |

`enregistrer()` renvoie `['identifiant' => …, 'statut' => 'en_attente'|'publie', 'url' => …]`. Elle lève `SoumissionNonModifiable` pour refuser la mise à jour d'une soumission publiée. `supprimer()` renvoie `false` si l'identifiant est inconnu.

Exemple d'implémentation, en requêtes préparées. La table, la connexion et l'adresse des articles sont celles de l'hôte : le framework n'en impose aucune.

```php
<?php

namespace MonApplication\Api;

use MVC\Api\Contract\DepotSoumissions;
use MVC\Api\Contract\SoumissionNonModifiable;
use MVC\Classe\Bdd;

final class DepotSoumissionsBreves implements DepotSoumissions
{
    public function enregistrer(array $soumission): array
    {
        $bdd = new Bdd('default');
        $existante = $this->trouver($bdd, $soumission['id_externe']);
        if ($existante !== null && $existante['statut'] === 'publie' && !$soumission['forcer']) {
            throw new SoumissionNonModifiable('Soumission déjà publiée.');
        }
        $sql = $existante === null
            ? 'INSERT INTO soumissions (id_externe, titre, contenu, image, statut, date_soumission)
               VALUES (:id_externe, :titre, :contenu, :image, \'en_attente\', NOW())'
            : 'UPDATE soumissions SET titre = :titre, contenu = :contenu, image = :image, date_maj = NOW()
               WHERE id_externe = :id_externe';
        $bdd->faireBindRequete($sql, [
            ['id_externe', $soumission['id_externe'], \PDO::PARAM_STR],
            ['titre', $soumission['titre'], \PDO::PARAM_STR],
            ['contenu', $soumission['contenu'], \PDO::PARAM_STR],
            ['image', $soumission['image'], $soumission['image'] === null ? \PDO::PARAM_NULL : \PDO::PARAM_STR],
        ]);

        return ['identifiant' => $soumission['id_externe'], 'statut' => $existante['statut'] ?? 'en_attente'];
    }

    public function supprimer(string $idExterne): bool
    {
        $bdd = new Bdd('default');
        $requete = $bdd->faireBindRequete(
            'DELETE FROM soumissions WHERE id_externe = :id_externe',
            [['id_externe', $idExterne, \PDO::PARAM_STR]]
        );

        return $requete !== 0 && $bdd->exploiterNbResultat($requete) > 0;
    }

    private function trouver(Bdd $bdd, string $idExterne): ?array
    {
        $requete = $bdd->faireBindRequete(
            'SELECT id_externe, statut FROM soumissions WHERE id_externe = :id_externe',
            [['id_externe', $idExterne, \PDO::PARAM_STR]]
        );
        $lignes = $requete === 0 ? [] : $bdd->exploiterResultat($requete);

        return $lignes[0] ?? null;
    }
}
```

Le statut `publie` et l'adresse de l'article (`url`) dépendent du flux de validation de l'hôte : relecture manuelle, puis publication.

## Tests

La suite « SAND Api » couvre ces cas :

- `ApiRoutageTest.php`, `ApiErefererTest.php` et `ApiDurcissementTest.php` : appels directs au routeur et à `Requete::depuisGlobales()` ;
- `ApiHttpTest.php` : requêtes HTTP réelles vers `php -S` sur `public/index.php`, lancé par `ServeurPhpIntegre.php` (un port libre par test, serveur arrêté dans `tearDown()`).

La clé est générée à chaque test. Le fichier de clés des tests HTTP est écrit dans un dossier temporaire, jamais dans `api/config/`. Le dépôt factice est `tests/phpunit/tests/DepotSoumissionsFactice.php`.
